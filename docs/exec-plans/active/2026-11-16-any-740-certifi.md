`50f79f98dac192b20dbf73f35c56f0b0c557ab267ff5199d1117cc1180b70785`.

`9cc2a774b5198dcff14d9be1e66091f538975d867ce029a96bce15a55dfd730f`,
and contains that root.

`security/trivy/verify-api-tls.py --require-patched` passed inside the final
production image. It inspects the actual Kernel, LBX source and LBX account
HTTPX/httpcore pool contexts (intentionally coupled to the pinned clients),
confirms their default CA sets equal the installed certifi bundle, and verifies
`CERT_REQUIRED` plus hostname checking. Real OpenSSL MemoryBIO handshakes reject
an untrusted synthetic certificate, accept it after adding it only to the
disposable in-memory context, and reject the wrong hostname. Temporary keys are
generated inside the container and deleted; no installed bundle, certificate
verification policy, credentials or customer data is modified. This proves TLS
handshakes, not real-provider conformance or live credentials.

The existing `security/trivy/verify-api-runtime.sh` passed against that exact
image: configured user `app`, non-root UID, required util-linux version and API
liveness. This is separate evidence from TLS and certifi remediation.

policy was changed.
